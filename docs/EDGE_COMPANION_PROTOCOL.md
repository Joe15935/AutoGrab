# Phase 2R implementation contract

Official MV3 Native Messaging, no TCP/CDP/session export. Python Core persists transport in the existing SQLite database. Edge starts the native host using `connectNative`; the host polls durable Core commands. First release implements only DRY_RUN through checkout. START_CHECKOUT is recognized but rejected as LIVE_NOT_ENABLED. No order/payment mutation exists.

Envelope (all keys required, no extras): `version:1`, `type`, `message_id` (UUID), `command_id` (UUID), `intent_id` (UUID or null for control), `provider:"bandwagon"`, `product_id` (numeric string or null for control), `timestamp` (UTC ISO), `payload` (strict object). Maximum UTF-8 frame: 65536 bytes. Replay message IDs rejected. Timestamp freshness 120 seconds at transport dispatch; durable commands receive fresh timestamp on first dispatch only.

Commands: PING, GET_STATUS, DISARM (null identity); OPEN_PRODUCT, START_DRY_RUN, START_CHECKOUT, RESUME_INTENT, CANCEL_INTENT (exact persisted identity). Product commands payload `{product:{name,url,period,cents,currency},mode:"DRY_RUN"}`; period annually or biennially; url only official public `/order/ecommerce/` path with no query/fragment. Control and CANCEL_INTENT payload `{}`. RESUME_INTENT has same product payload and is only allowed for a paused original intent after a PAGE_OPENED report showing normal page returned. No automatic replay of a dispatched mutation.

Events: EDGE_READY, PAGE_OPENED, PRODUCT_VERIFIED, CART_READY, CHECKOUT_READY, ORDER_CREATED, INVOICE_FOUND, PAYMENT_READY, LOGIN_REQUIRED, HUMAN_CHALLENGE_REQUIRED, SOLD_OUT, SITE_CHANGED, FAILED. Event payload only optional fields `version` (extension semver), `tab_id` (integer), `url` (sanitized official URL), `stage` (uppercase identifier), `code` (uppercase identifier), `login` (VALID/REQUIRED/UNKNOWN), `challenge` (NONE/REQUIRED/UNKNOWN), `cart_id` (safe identifier), `resume_from` (uppercase identifier), `mutation_uncertain` (boolean). EDGE_READY uses null identity and command_id as connection UUID, version required. ORDER/INVOICE/PAYMENT events rejected by Core in this release; an extension cannot assert receipt evidence.

Execution ownership: service worker one active intent, durably persists checkpoint and each mutation before dispatch in chrome.storage.local; never replay a DISPATCHED mutation. Content adapter exposes only fixed operations over a fresh page; rejects challenges before any DOM action. It reads top-level challenge presence only, no token/iframe contents. After challenge clears it reports ordinary PAGE_OPENED; Core issues RESUME_INTENT for the same identity, while uncertain mutation first needs its resulting page verified. Disconnect pauses and disables execution. Reconnect status is read-only; explicit Core resume reuses the same intent. Native host owns one process lock, origin checks, schema, identity checks, heartbeat and email dedup.

Python module ownership: `autograb/edge/protocol.py`, `broker.py`, `native_host.py`. Public API `EdgeBroker(store)`: `enqueue(type,intent_id=None,product_id=None,payload=None)->dict`, `next_command()->dict|None`, `handle_event(message)->dict`, `disconnect()`, `status()->dict`; additional helpers allowed. Existing IntentStore owns identity. Add edge_state/checkpoint metadata to existing purchase_intents rather than another orders database. `handle_event` returns accepted status and optional human_notification payload; host performs one deduped email. Host launched `python -m autograb.edge.native_host --root ABS_ROOT --extension-id ID ORIGIN`. Fixed native host name `com.autograb.edge`.

Extension ownership: `manifest.json`, `service-worker.js`, `protocol.js`, `content.js`, `popup.html/js/css`, Node protocol/worker tests. Provider separate `providers/bandwagon/adapter.js` as classic script assigns `globalThis.AutoGrabBandwagon`. Adapter interface `detectPage`, `verifyProduct(expected)`, `configureProduct(expected)`, `addToCart(expected)`, `verifyCart(expected)`, `openCheckout(expected)`, `verifyCheckout(expected)`, `detectLogin`, `detectChallenge`, `detectOrder`, `detectInvoice`, `detectPaymentReady`; expected `{name,url,period,cents,currency,product_id}`. Read methods return `{ok,stage,code,login,challenge,cart_id?}`. Action methods return same plus `action` and only act after re-verification. `configureProduct` opens exact observed product link or adjusts configuration billing; `addToCart` only configuration POST; `openCheckout` only observed checkout navigation. Throwing indicates fail closed. No selector or arbitrary script from Python accepted. Fixture tests use existing Playwright only against offline fixture routes, never for real Edge.

Root owns CLI/install/docs/package integration. Public CLI routes `open-session` to normal Edge and online preflight/arm/reconcile away from retired authenticated Playwright. Historical direct helper APIs remain regression only. New commands: edge-install, edge-status, edge-open, edge-dry-run --product-id ID, edge-resume --intent-id UUID, edge-cancel --intent-id UUID. Popup shows status without account fields. Original 405 tests retained unchanged.

## Real-page refinements

The public catalog does not display the WHMCS product name, USD label or logged-in marker. Its default billing radio can be monthly even when the selected product has only longer periods. `selectBillingPeriod(expected)` selects the unique observed non-form “1 Year” radio once. The worker journals this as SELECT_PUBLIC_BILLING, then verifies the displayed annual amount and exact PID/annual link. `PUBLIC_BILLING_SELECTED` precedes OPEN_CONFIGURATION. The public result is only PUBLIC_PRODUCT_VERIFIED; exact full name, USD amount and billing period must be verified on configuration before PRODUCT_VERIFIED and before Add to Cart.

Configuration inspection is read-only. In this DRY-only milestone, config/cart actions may proceed with UNKNOWN login on an ordinary page after all product/form/cart checks; explicit login prompts and challenges stop. UNKNOWN is never promoted to VALID. CHECKOUT_READY still requires a positive authenticated marker; no order/receipt event is accepted. No hidden credential values are read.

The worker persists the initial configuration identifier, checks it on later reads, and sends mutation messages to the browser's observed documentId. Content rechecks the bound configuration identifier immediately before dispatch. A later configuration index is rejected before the configuration POST. Index zero does not prove the cart was empty before following an add link; true initial empty-cart preflight remains unverified. Unknown multi-item carts are never cleared.

Known pre-dispatch refusal can return action:NONE and mark the journal NOT_APPLIED; a lost response never can. Extension reload/native reconnect preserves the original intent and requires explicit Core RESUME_INTENT after a normal page is observed. Reload is not permission to repeat a previously dispatched cart request.

Checkout sprint: FAILED is an observable pause, not a terminal state. Resuming a CART_READY checkpoint first checks the live cart/checkout. A matching cart is reused. Only explicit CART_EMPTY, confirmed again in a new GET document, permits up to two same-intent cart reconstructions, with the previous journal archived and the count persisted in existing extension storage. Existing PAGE_OPENED codes CART_STATE_STALE / CART_REBUILDING carry the observation; Core only resets the product verification checkpoint on a valid RESUME_INTENT. Core refuses any order/invoice/payment evidence or submit_started_at. This is a newly justified cart operation, never a replay of the prior ticket or a relaxation of ORDER_SUBMITTING protection.
